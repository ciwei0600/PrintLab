# PrintLab 项目全流程

从当前阶段推进本轮授权工作，保持需求、设计稿、真实模型、切片与实物之间可追溯。此技能规定执行和交接方式；只有实际运行过的检查才算通过，文档流程不代表后台已自动运行。

## 接手与范围

1. 从当前工作目录、项目记录或用户指定位置定位 PrintLab 与模型归档目录，读取各自 `AGENTS.md`。不要写死本机路径、项目 ID、机型、材料或凭据。
2. 读取 PrintLab 的 `Context/workflow.md`、`Context/profile.md`、`Context/agent-policy.json`，目标项目的 `project.json`、`brief.md`、`decisions.md`、`latest_session` 指向的交接和本阶段证据。以项目关联的实际设备卡为准，不从模板机型猜测设备。
3. 确认当前版本、用户已选目标、真实模型是否已获确认、本轮允许推进的阶段、待测项与禁止动作。已有选择和有效确认直接接续；关键文件变化则重新检查受影响的阶段。只读问题只检查和解释，不改模型或状态。
4. Sarah 负责设备、材料和配件条件；Mike 负责工具、工作台和流程；具体执行者负责模型与证据。先查已有角色和任务，仅在用户明确要求时创建会话或派发子 Agent；没有实际参与不能署名为独立复核。

## 阶段与放行条件

| 阶段 | 工作和交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 需求与零配件 | 用途、尺寸、零配件清单、设备限制、验收要求；区分实测、用户确认、设计余量和假设 | 关键约束明确；缺尺寸时可先布局，涉及配合的未决项不得伪装为定稿 |
| 2. 外形选图 | 可比较的外形方案，保存原图、来源、提示词、用户选择和关键特征 | 用户选定准确原稿；已有选择无需重选 |
| 3. 空间解释 | 同款四套正/右/俯三视图，保留用户选定整套和原图哈希，说明遮挡与冲突 | 选定空间参考；冲突明确处理，不替换原稿来迎合容易建模的方案 |
| 4. 真实外观建模 | 可编辑源、参数、同源三视图及匹配原稿角度的斜视；先做必要的配件空间可行性 | 导出与源模型一致，能与选定目标真实比较 |
| 5. 内部对照返工 | 按外观审稿技能生成对照、差异、评分和检查证据；不合格继续改模型 | 至少 90/100、关键特征通过、无重大偏差、证据完整且 appearance 检查成功 |
| 6. 用户外观审稿 | 交付准确版本的真实三视图、原稿对照、分项分数和残余差异 | 用户明确接受这份真实模型，确认绑定版本和文件，release 检查成功 |
| 7. 正式结构工程 | 内腔、安装座、孔位、背盖、紧固、走线、开关运动、拆装路径和稳定性；必要时设计同源试模 | 关键接口、壁厚、公差、干涉、承力与稳定性检查有证据；改变可见外形返回阶段 4–6 |
| 8. 材料与切片 | 读实际设备与供料配置，确定材料/配色/分件，比较摆放、支撑和耗时；输出正式切片工程与预览 | 当前模型和实际切片匹配，制造检查通过，记录用户对材料与重要取舍的决定 |
| 9. 当次打印 | 核验具体版本、切片哈希、盘号、设备、材料映射、实时状态与清板事实；按任务记录单次发送、读回与对账 | 用户明确授权这次打印，且现行批准、清板和发送窗口有效；未满足保持待打印 |
| 10. 实物验收与归档 | 核对成形、尺寸、装配、外观、手感、强度和使用功能；用户反馈绑定实际版本与材料 | 用户确认实物结果才标为实物验收完成；失败项回到对应阶段修订 |

这些是工作阶段，不是可直接写入 `project.json` 的状态枚举。使用当前工作台支持的命令与字段保存，不能凭表格名称发明软件能力。纯功能件或既有零件的局部尺寸调整，可注明无外形选图阶段及理由；已有外观目标的作品不能借此绕过 90 分门槛。

## 建模与外观循环

- 建模、绘图、导出和模型检查使用已安装的 `parametric-cad-automation`。先形成设计契约：毫米、原点/基准面、命名参数、特征顺序、输出格式和未测尺寸假设。工具按几何需要选用，保留可编辑来源与受保护接口。
- 阶段 2–6 使用 `printlab-design-review`；优先读取工作台内 `Skills/printlab-design-review/SKILL.md`，安装副本位于 Codex 技能目录。它维护评分协议与 `design-check` 证据格式，本技能不复制或放宽规则。依赖缺失时报告并定位原有技能，不把未运行检查写成通过。
- 固定评分为轮廓 30、比例 20、曲面 20、特征布局 20、细节 10。分数来自实际视觉观察与扣分依据，程序计算加权分并验证文件关联；不是客观像素相似率，也不自动代表独立复核。
- 内部循环：模型 → 同源渲染 → 对照/评分 → 改模型。低于 90 或证据不齐继续返工，不能只改分数、变形参考图或用 AI 图冒充模型渲染。必要信息缺失时保留未通过状态，索取缺项，不以合格稿交付。
- 用户反馈循环：保留原话 → 新版本 → 重新内审 → 再交审。结构修改影响外形时同样返回该循环；只改内部结构也需重新验证受影响模型和文件关联，不能沿用失效哈希。

## 制造与设备边界

阶段 7–10 读取 [结构、切片与打印交接](references/manufacturing-handoff.md)，使用项目现有命令和真实工具，不另造发送通道。

“继续”“选这款”“外观通过”不等于打印授权。“先不要打印”持续有效，直到用户明确授权具体打印任务；试模也属于打印。若本轮只要求外观或文档，不自行开始切片、设备动作或采购。已有明确授权不重复询问，但文件、设备或材料变更须重新核对授权适用性。

## 接续和归档

- 每轮交接记录：当前阶段与版本、已确认目标、实际完成工作、检查及证据位置、未决假设、用户决定、授权范围和下一步。用当前 `printlab handoff --help` 确认参数；维护项目 brief/decisions 与实际交接的一致性，不覆盖历史决定。
- CAD、导出、预览、评分和切片必须关联同一版本及来源；旧交付件保留。归档到 3DPrint 时按其 `drawings/<model-name>/vYYYYMMDD-N/` 规则，保存生成源、主要 CAD、说明、必要证据和文件清单。
- 只有发生实际结果才更新对应状态：文件生成、预检成功、发送成功、机器完成、用户实物验收分别记录。报告关键未完成项，不用软件“完成”代替实物验证。
- 对外分享、WebDisk 上传和购买仅在相应用户请求范围内执行；上传按项目现有读回与哈希校验要求。源码/文档按项目版本管理规则提交，排除个人数据和凭据；技能更新不伪造运行版本发布。
